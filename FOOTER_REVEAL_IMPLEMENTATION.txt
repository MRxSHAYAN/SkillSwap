================================================================================
SKILLSWAP - REVEAL FOOTER IMPLEMENTATION GUIDE & ARCHITECTURE REFERENCE
================================================================================

1. PROBLEM
----------
Standard web layouts append the footer immediately following the last page section
in normal document flow. In that model, scrolling down simply pushes the entire footer
up from below the fold like any other block element. 

The objective was to implement an editorial, agency-grade "reveal footer" (curtain
effect) where:
- The main website content acts as an opaque top/front layer.
- The footer sits physically underneath this main layer.
- While the user scrolls through the website, the footer remains completely hidden behind
  the content.
- As the user reaches the end of the page, the main content slides away upward,
  progressively unmasking/revealing the footer resting underneath.
- Upon full reveal, the footer rests naturally at the bottom of the viewport with all
  interactive elements (links, social buttons, back-to-top) fully accessible.


2. WHY THE ORIGINAL "sticky bottom-0 min-h-screen" APPROACH BEHAVED INCORRECTLY
--------------------------------------------------------------------------------
The initial attempt:
  <footer className="... sticky bottom-0 z-10 min-h-screen">
did not produce the desired reveal effect for several fundamental CSS reasons:

a. In-Flow Positioning vs. Layering:
   `position: sticky` is an IN-FLOW positioning model. An element remains in normal
   document flow until a scroll threshold is met. When declared at the bottom of a page,
   the footer starts after the last section. It does not place the footer behind the page.

b. Containing Block Boundary:
   A sticky element cannot stick outside its parent containing block. When placed at the
   end of the parent wrapper (`PublicLayout`), its natural flow position is already at the
   very bottom of that container. With `bottom: 0`, the element will only stick if its
   bottom edge would otherwise scroll *above* the viewport bottom *within its container*.
   Because the container terminates right where the footer ends, there is zero remaining
   scroll space for the element to stick. It either behaves like a static element or sticks
   prematurely in front of content.

c. Inverted Stacking Context (z-10):
   Setting `z-10` on the footer while leaving main content at default or equivalent z-index
   places the footer ON TOP of content rather than underneath it. A reveal effect strictly
   requires the main content to have the higher stacking order (`z-10`) with an opaque
   background, and the footer to have the lower stacking order (`z-0`).

d. Excessive Height (min-h-screen):
   Applying `min-h-screen` forced the footer to consume 100vh of document height. Rather
   than allowing the main content to smoothly unmask a naturally sized footer (~400-500px),
   it created an enormous empty scroll block that looked like a separate blank page stuck
   at the bottom.


3. FINAL DOM STRUCTURE
----------------------
The implementation in [PublicLayout.jsx](file:///c:/Drive/WorkSpace/Development/Projects/mern%20stack%20projects/SkillSwap/frontend/src/layouts/PublicLayout.jsx) uses a clean 2-layer model with a transparent dynamic scroll spacer:

  Page Wrapper (`relative min-h-screen bg-black`)
  │
  ├── 1. Main Content Layer (`relative z-10 bg-white min-h-screen flex flex-col shadow-2xl`)
  │    ├── <Navbar /> (fixed top-0, z-50)
  │    └── <main className="flex-1">
  │         └── <Outlet /> (Home, About, ExploreSkills, Reviews, Contact, Auth, etc.)
  │
  ├── 2. Reveal Spacer Canvas (`relative w-full pointer-events-none`, height = `footerHeight`)
  │    └── Transparent scroll trigger tracking `scrollYProgress`
  │
  └── 3. Footer Layer (`fixed bottom-0 left-0 w-full z-0 origin-bottom`, motion.div)
       └── <Footer /> (Rendered under main layer, unmasked as spacer scrolls into view)


4. MAIN-CONTENT LAYER
---------------------
- Role: Acts as the foreground "curtain" that covers the footer during browsing.
- Styling: `relative z-10 bg-white min-h-screen flex flex-col shadow-[0_25px_50px_-12px_rgba(0,0,0,0.5)]`
- Why `bg-white`: Opaque background prevents the underlying fixed footer from shining
  through while reading page sections.
- Why `min-h-screen`: Guarantees that short routes (e.g. ForgotPassword) still occupy the full
  viewport before revealing the footer.
- Why `shadow-2xl`: Projects a subtle elevation drop shadow onto the footer as the curtain pulls
  away, providing physical depth.


5. FOOTER LAYER
---------------
- Role: The background layer anchored at the bottom of the viewport beneath the main content.
- Styling: `fixed bottom-0 left-0 w-full z-0 origin-bottom`
- Why `fixed bottom-0`: Keeps the footer pinned to the viewport bottom. As the user scrolls
  through the body, the main content moves up and out of the way, creating the illusion of
  unmasking the stationary footer underneath.
- Why `z-0`: Guarantees the footer remains physically behind the main content (`z-10`) until
  uncovered.


6. Z-INDEX RELATIONSHIP
-----------------------
- Navbar: `z-50` (Always accessible at top of viewport)
- Main Content Layer: `z-10` (Foreground curtain)
- Reveal Spacer: `pointer-events-none` (Allows clicks to pass through to revealed footer)
- Footer Layer: `z-0` (Underlay)

Because the Main Content Layer has an opaque background and higher z-index (`z-10`), all click
and hover events on page content target the main layer. When the user scrolls past the main content
and the spacer unmasks the footer, clicks in that uncovered region pass cleanly to the footer links.


7. SCROLL/REVEAL MECHANISM & PREVENTING OVERLAP
-----------------------------------------------
The core challenge in a reveal footer is preventing the last section of the website from being
obscured by the fixed footer.

Without a bottom spacer:
The main content would end right at the viewport bottom, meaning the user could never scroll
further to uncover the fixed footer underneath.

The Solution:
A transparent Reveal Spacer `<div ref={revealTriggerRef} style={{ height: footerHeight }}>` is
placed immediately after the Main Content layer in normal document flow.
- A `ResizeObserver` measures `footerRef.current.offsetHeight` dynamically.
- Desktop: ~420px spacer.
- Tablet: ~480px spacer.
- Mobile: ~620px spacer (handling stacked columns automatically).
- When the user reaches the end of the main page, the browser has an additional `footerHeight`
  pixels of document to scroll through.
- As the user scrolls through this empty spacer, the main content moves upwards off-screen by
  `footerHeight` pixels, revealing 100% of the footer with zero overlap.


8. FRAMER MOTION IMPLEMENTATION
-------------------------------
Framer Motion links the reveal smoothly to page scroll position:

```jsx
const { scrollYProgress } = useScroll({
  target: revealTriggerRef,
  offset: ["start end", "end end"],
});

const y = useTransform(scrollYProgress, [0, 1], [-40, 0]);
const opacity = useTransform(scrollYProgress, [0, 1], [0.6, 1]);
const scale = useTransform(scrollYProgress, [0, 1], [0.98, 1]);
```

Mapping Flow:
  scroll progress across reveal trigger (0 -> 1)
        ↓
  footer reveal progress (0% -> 100%)
        ↓
  y: -40px -> 0px (gentle parallax lift into place)
  opacity: 0.6 -> 1.0 (emerges from submerged depth into full clarity)
  scale: 0.98 -> 1.0 (subtle scale expansion)

When `scrollYProgress = 1`, the footer is in its exact rest state (`y: 0, opacity: 1, scale: 1`).


9. TAILWIND CSS IMPLEMENTATION
------------------------------
Key Tailwind utility classes used:
- `relative`: Establishes positioned context for z-index layering and container containment.
- `min-h-screen`: Ensures element fills at least 100vh so short pages don't show the footer prematurely.
- `z-10`: Raises Main Content stacking context above the footer.
- `bg-white`: Opaque background preventing underlay shine-through.
- `shadow-[0_25px_50px_-12px_rgba(0,0,0,0.5)]`: Smooth ambient drop shadow along the bottom edge.
- `fixed bottom-0 left-0 w-full`: Pinned position for the footer at the viewport floor.
- `z-0`: Keeps footer beneath the main content layer.
- `pointer-events-none`: Allows clicks through the transparent spacer to the revealed footer.
- `origin-bottom`: Centers Framer Motion scale transforms against the bottom viewport edge.


10. GLOBAL CSS ALTERNATIVE
--------------------------
If Tailwind CSS and Framer Motion were not used, the identical reveal effect can be implemented
using pure vanilla CSS:

```css
/* Page Root */
.page-wrapper {
  position: relative;
  min-height: 100vh;
  background-color: #000000;
}

/* Foreground Curtain */
.main-content-layer {
  position: relative;
  z-index: 10;
  background-color: #ffffff;
  min-height: 100vh;
  box-shadow: 0 25px 50px -12px rgba(0, 0, 0, 0.5);
  display: flex;
  flex-direction: column;
}

/* Scroll Spacer (height populated via JS or var(--footer-height)) */
.reveal-spacer {
  position: relative;
  width: 100%;
  height: var(--footer-height, 450px);
  pointer-events: none;
}

/* Underlay Footer */
.reveal-footer-layer {
  position: fixed;
  bottom: 0;
  left: 0;
  width: 100%;
  z-index: 0;
}
```

12. HOW TO TEST THE EFFECT
--------------------------
1. Start frontend dev server:
   ```bash
   cd frontend
   npm run dev
   ```
2. Open `http://localhost:5173/` in a browser.
3. Scroll down through the Home page.
   - Observe that the footer is completely hidden behind the white/dark sections while scrolling.
4. As you scroll past the final newsletter section:
   - Notice the front layer sliding up like a curtain with a soft drop shadow.
   - Notice the footer gently scaling (0.98 -> 1) and brightening (0.6 -> 1) into place.
5. Once at the bottom:
   - Click any footer link (e.g. "Explore Skills", "Reviews", "Terms of Service", social icons).
   - Test the "[Back to top ↑]" button to see the front layer smoothly slide back down over the footer.
6. Test Responsive:
   - Open Developer Tools (F12) and toggle device toolbar (Ctrl+Shift+M).
   - Test Mobile (e.g. iPhone 14/15, 390px width) and Tablet (iPad, 768px/820px width).
   - Confirm that the spacer dynamically adjusts to the taller stacked mobile footer height.


13. HOW TO REMOVE OR DISABLE IT
-------------------------------
To revert back to a standard static in-flow footer at any time, edit `PublicLayout.jsx`:
Replace the return statement with:

```jsx
export default function PublicLayout() {
  return (
    <div className="min-h-screen flex flex-col justify-between bg-white text-black">
      <Navbar />
      <main className="flex-1">
        <Outlet />
      </main>
      <Footer />
    </div>
  );
}
```
This instantly removes the layering, spacer, and Framer Motion transforms, returning the footer
to standard document flow.
