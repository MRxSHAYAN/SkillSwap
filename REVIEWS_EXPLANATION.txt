====================================================================
                SKILLSWAP REVIEWS & RATING SYSTEM
====================================================================

This document explains how the Reviews, Ratings, and Feedback system
works in your SkillSwap backend application.

--------------------------------------------------------------------
1. OVERVIEW OF THE REVIEWS SYSTEM
--------------------------------------------------------------------
The Reviews system enables users to give and receive feedback after
completing a skill exchange.

Key Highlights:
- Rated 1 to 5 Stars: Rating must be an integer between 1 and 5.
- Skill Context: Each review is linked to a specific skill (e.g. "React", "Spanish", "Guitar").
- Duplicate Prevention: A user can review another user only ONCE per skill.
- Self-Review Prevention: Users cannot leave reviews for themselves.
- Automatic Summaries: The API calculates average ratings and 1-5 star distributions for any user.
- Security: Reviews can only be updated by the original author and deleted by the author or an admin.


--------------------------------------------------------------------
2. DATABASE SCHEMA (backend/src/models/Review.js)
--------------------------------------------------------------------
The Review model stores reviews in MongoDB with the following fields:

Field        Type      Rules & Validation
--------------------------------------------------------------------
reviewer     ObjectId  Ref to User (ID of user giving feedback). Required.
reviewee     ObjectId  Ref to User (ID of user receiving feedback). Required.
skill        String    Skill name. Trimmed, required.
rating       Number    Integer between 1 and 5. Required.
comment      String    Text feedback (5 to 1000 characters). Required.
timestamps   Boolean   Automatically creates createdAt and updatedAt fields.

Indexes & Constraints:
1. Self-Review Check: Schema pre-save hook prevents reviewer == reviewee.
2. Unique Compound Index: { reviewer: 1, reviewee: 1, skill: 1 } ensures a user 
   cannot review the same user twice for the same skill.

3. API ENDPOINTS & USAGE
--------------------------------------------------------------------

1) CREATE A REVIEW (Protected - Requires JWT Token)
   POST /api/reviews
   Headers: 
     Authorization: Bearer <JWT_TOKEN>
     Content-Type: application/json

   Request Body:
   {
     "reviewee": "64f1a2b3c4d5e6f7a8b9c0d1",
     "skill": "React Development",
     "rating": 5,
     "comment": "Awesome mentor! Taught me hooks and context API clearly."
   }

   Response (201 Created):
   {
     "success": true,
     "message": "Review created successfully",
     "data": {
       "_id": "64f1a2b3c4d5e6f7a8b9c0d9",
       "reviewer": {
         "_id": "64f1a2b3c4d5e6f7a8b9c0d0",
         "fullName": "Alice Johnson",
         "email": "alice@example.com",
         "country": "USA"
       },
       "reviewee": {
         "_id": "64f1a2b3c4d5e6f7a8b9c0d1",
         "fullName": "Bob Smith",
         "email": "bob@example.com",
         "country": "Canada"
       },
       "skill": "React Development",
       "rating": 5,
       "comment": "Awesome mentor! Taught me hooks and context API clearly.",
       "createdAt": "2026-07-31T14:30:00.000Z",
       "updatedAt": "2026-07-31T14:30:00.000Z"
     }
   }


2) GET REVIEWS FOR A USER (Public)
   GET /api/reviews/user/:userId

   Response (200 OK):
   {
     "success": true,
     "message": "Reviews retrieved successfully",
     "summary": {
       "totalReviews": 2,
       "averageRating": 4.5,
       "ratingDistribution": {
         "1": 0,
         "2": 0,
         "3": 0,
         "4": 1,
         "5": 1
       }
     },
     "data": [ ... array of reviews populated with reviewer info ... ]
   }


3) GET REVIEWS GIVEN BY A USER (Public)
   GET /api/reviews/given/:userId

   Response (200 OK):
   {
     "success": true,
     "count": 1,
     "message": "Reviews given by user retrieved successfully",
     "data": [ ... array of reviews written by this user ... ]
   }


4) GET A SINGLE REVIEW BY ID (Public)
   GET /api/reviews/:id

   Response (200 OK):
   {
     "success": true,
     "data": { ... review object populated with reviewer and reviewee info ... }
   }


5) UPDATE A REVIEW (Protected - Author Only)
   PUT /api/reviews/:id
   Headers: Authorization: Bearer <JWT_TOKEN>

   Request Body (all fields optional):
   {
     "rating": 4,
     "comment": "Updated feedback: Great sessions overall!"
   }

   Response (200 OK):
   {
     "success": true,
     "message": "Review updated successfully",
     "data": { ... updated review object ... }
   }


6) DELETE A REVIEW (Protected - Author or Admin Only)
   DELETE /api/reviews/:id
   Headers: Authorization: Bearer <JWT_TOKEN>

   Response (200 OK):
   {
     "success": true,
     "message": "Review deleted successfully"
   }


--------------------------------------------------------------------
4. VALIDATION & ERROR HANDLING
--------------------------------------------------------------------
- 400 Bad Request: Invalid Mongo ID, invalid rating range, or trying to review oneself.
- 401 Unauthorized: Missing or invalid JWT token.
- 403 Forbidden: Attempting to edit/delete a review created by another user.
- 404 Not Found: Target review or user does not exist.
- 409 Conflict: Review for the same user and skill already submitted.
- 422 Unprocessable Entity: Failed express-validator input checks (e.g. comment too short).

5. HOW TO TEST WITH CURL / POSTMAN
--------------------------------------------------------------------

Step 1: Login to get a JWT token
  curl -X POST http://localhost:5000/api/auth/login \
    -H "Content-Type: application/json" \
    -d "{\"email\":\"alice@example.com\",\"password\":\"password123\"}"

Step 2: Create a review for User B
  curl -X POST http://localhost:5000/api/reviews \
    -H "Content-Type: application/json" \
    -H "Authorization: Bearer <YOUR_TOKEN_HERE>" \
    -d "{\"reviewee\":\"USER_B_ID\",\"skill\":\"JavaScript\",\"rating\":5,\"comment\":\"Great teaching style!\"}"

Step 3: Fetch all reviews for User B
  curl -X GET http://localhost:5000/api/reviews/user/USER_B_ID
